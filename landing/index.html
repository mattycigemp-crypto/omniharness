The Wedge

Built on routing,
not around it.

Generic agents were built for one provider and bolt routing on afterward. OmniHarness inverts that: OmniRoute is the execution layer. Provider selection, quota, failover, and model translation stay in the gateway — one integration point instead of N SDKs.

you ── OmniHarness ── internal/gateway ─────────────────────────────┐ ↓ │ OmniRoute (one endpoint) │ ├─ claude/sonnet │ auto/best-coding │ ├─ openai/gpt-5 │ auto/cheap │ ├─ google/gemini-flash │ free-stack combo │ └─ failover · quota · routing · translation │ │ swap gateway → entire test suite runs offline ──────────┘
Working Modes

Four gears.
One Ctrl+E.

Cycle through modes as the work changes. Permission level is a separate axis — set it independently with Shift+Tab without leaving the current mode.

◇plan

Think before acting. Lays out a full plan and checkpoints with you before any file changes. Good for scoping unfamiliar work.

Ctrl+E → plan
◈build

The workhorse. Reads, edits, runs tests, fixes failures. One tight loop until the intent is satisfied.

Ctrl+E → build
◎research

Read-only exploration. Searches, reads, summarizes — no writes. Understand a codebase before deciding what to change.

Ctrl+E → research
⚡crazy

Full autonomy. Fans an independent plan across parallel worker agents. All approvals bypassed. One swarm, many lanes.

Ctrl+E → crazy
[ perm ] Permission axis — independent of mode. Shift+Tab cycles ○ manual → ◐ accept edits → ● bypass. Crazy mode forces bypass automatically.
Crazy Mode

One intent.
Many workers.

CRAZY mode fans a plan across parallel worker agents. Each lane gets its own context and tool loop. The swarm rail shows every lane live — in a single unified transcript.

The only harness where "do it all" means do it all at once.

The Terminal

Every pixel earns
its place.

Everything on screen makes agent intent, action, and history legible — nothing is chrome for chrome's sake.

[ scrollback ]
Native scrollback is the history
Settled turns flow into your terminal's own buffer. No parallel log. The full transcript is restored on exit via the alt-buffer.
[ route-ribbon ]
Route ribbon
Every reply is labelled with the provider it came from. Failovers appear inline — you always know what ran and why.
[ ctx-meter ]
Context meter
Per-model window usage, live. Colour-coded zones: ok → warn → danger. Knows the window for every model in the routing catalog.
[ tool-cards ]
Per-tool cards with diffs
Each tool call is a collapsible card: name, input, result. File edits show the unified diff inline. History compresses behind you.
[ scoped-acl ]
Scoped-trust approvals
"Trust this command exactly" or "trust this tool" — not all-or-nothing. Scope is remembered for the session.
[ input-buf ]
Input queuing
Type your next instruction while the agent is still running. It's queued and delivered the moment the run finishes.
[ ^Y · osc52 ]
OSC 52 clipboard copy
Ctrl+Y copies the last code block over OSC 52 — works over SSH where the clipboard is normally inaccessible.
[ decset-2026 ]
Tear-free streaming
DECSET 2026 synchronized output suppresses partial-render flicker. Probed at launch; gracefully skipped if unsupported.
Get Started

Up in five
commands.

1

Install

Requires Node.js 20+. Installs the TypeScript TUI launcher globally.

bash
npm install -g omniharness-cli
2

Point it at your gateway

Three environment variables. Your API key is held in memory only — never written to config, logs, or telemetry.

bash
export OMNIROUTE_URL=http://localhost:20128
export OMNIROUTE_API_KEY=sk-your-key    # held in memory only
export OMNIROUTE_MGMT_TOKEN=mt-optional  # enables MCP tools
3

Verify the connection

Doctor checks the gateway and shows the routing catalog. The key is masked to key_<last4> — it never appears in output.

bash
omniharness doctor

endpoint    http://localhost:20128
api key     key_9999
catalog     reachable · 7622 models (38 auto/*)
combos      3 configured · free-stack, Kimi Coding, deepseek

ok — the gateway is reachable.
4

Launch the TUI

Navigate to your project and run. The TUI opens in the alternate buffer; your terminal history is preserved on exit.

bash
cd your-project
omniharness
5

Pick your mode and go

Press Ctrl+E to cycle modes. Shift+Tab adjusts the permission level. Type your intent and press Enter.

keys
# cycle working mode
Ctrl+E      plan → build → research → crazy

# cycle permission level
Shift+Tab   ○ manual → ◐ accept edits → ● bypass

# slash commands
/help       list all commands
/find       search transcript
Ctrl+C      cancel run / quit
omniharness doctor
❯

endpoint http://localhost:20128
api key key_9999
mgmt token not set
catalog reachable · 7622 models (38 auto/*)
combos 3 configured · free-stack, Kimi Coding, deepseek

ok — the gateway is reachable.

Architecture

Two front-ends.
One Go core.

The orchestration logic lives in Go: runtime, event bus, tool registry, session persistence. Front-ends are thin adapters. The TypeScript TUI ships today; web and desktop share the same core without touching it.

tree
omniharness/
├── cmd/omniharness/        Go entry point
├── internal/
│   ├── gateway/            OmniRoute adapter  ← swap this for offline tests
│   ├── runtime/            agent loop · event bus · session store
│   ├── orchestrator/       plan / build / research / swarm logic
│   └── tools/              tool registry + scoped trust
├── npm/                    TypeScript TUI (Ink/React)  ← ships today
│   └── src/
│       ├── ui/             Ink components (termcaps · palette · groups…)
│       └── agent/          mastraEngine — wires Go runtime to the TUI
├── web/       (roadmap)    React SPA · browser front-end
└── desktop/   (roadmap)    Tauri shell · native OS integration
